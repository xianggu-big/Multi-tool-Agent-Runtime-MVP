**问题**：做到什么程度算"做对了"？用什么客观指标衡量？

**参考答案（默认假设，可推翻）**：三条都可量化、都可复现——

| # | 标准 | 度量方式（本项目已有手段） |
|---|---|---|
| 1 | **功能**：子任务在独立上下文运行，主 Agent 汇总出结构化报告 | 结果字段齐全且通过 Zod 校验（确定性断言，非"看起来对"） |

## Q3. 任务结构

**问题**：任务是「固定流程」（步骤可枚举）还是「开放式探索」（需试错）？

**参考答案（默认假设，可推翻）**：**两者都有，必须按依赖图分流**——

| 任务形状 | 例（本项目） | 是否扇出 |
|---|---|---|
| 天然分区、零依赖 | 审计 3 个子目录 / 调研 4 个独立来源 / 批量清点多个仓库 | ✅ 并行 |
| 有增量依赖 | 跨模块重构、追一个 bug 的调用链、每一节依赖上一节的文档 | ❌ 串行（拆了反而更差） |

**判据（写进主 Agent 提示词与代码）**：*子任务之间是否零依赖、是否不需要对方的中间结果*。是 → 扇出；否 → 串行或交给单个 Agent。
**先规则预筛（按目录/来源天然分区）+ 再由主 Agent 细化**，而不是让主 Agent 从零想拆法。

**依据**：SOTA 共识——并行只在子任务真正独立时收益为正；对不独立的活做扇出，等于付 15× token 买一堆对账 bug。

## Q4. 硬约束

**问题**：有没有硬性约束（安全/成本/延迟/合规/兼容）？

**参考答案（默认假设，可推翻）**：

1. **向后兼容**：不得破坏单 Agent 路径，现有 98 个测试必须继续全绿。
2. **成本封顶**：扇出宽度 ≤ 4、层级深度 ≤ 2；总 token 预算在"主 + 各子"之间**显式分配**，不允许子 Agent 无限追加。
3. **只读优先**：沿用现有边界（无写/删工具；破坏性动作一律 `requiresHuman`）。
4. **技术栈冻结**：不引入外部队列/消息中间件/向量库；单机 Node + SQLite。

**依据**：知识库反模式清单（无界扇出 / 过度分解 / 共享可变状态）；多 Agent 约 15× token，成本必须显式封顶。

## Q5. 边界（明确不做什么）

**问题**：明确**不**做什么？

**参考答案（默认假设，可推翻）**：

- ❌ 不做跨进程/分布式调度（本期单机进程内并发；接口预留可切换）
- ❌ 不做子 Agent 之间自由对话（Actor 消息模型留到确有多元协商需求时再上）
- ❌ 不做自动写/删（继承 misc 的只读边界）
- ❌ 不做"子 Agent 再拆子 Agent"的深层递归（深度 ≤2，防成本失控）

**依据**：结构层优先——边界靠"没有那个工具/没有那个通路"来保证，而不是靠提示词请求模型配合。

## Q6. 模型策略与成本

**问题**：① 延迟/成本敏感度？② 有多少"封闭答案集、高频重复"的窄决策？③ 是否接受分档？④ 供应商约束？

**参考答案（默认假设，可推翻）**：接受分档（形态 **B + C 混合**）——

| 角色 | 档位 | 参数（本项目已验证的 DeepSeek 可调项） |
|---|---|---|
| 主 Agent（拆分/汇总/裁决） | 强力档 | `deepseek-v4-pro` 或 `flash` + `thinking=enabled` + `effort=low` |
| 子 Agent（执行子任务） | 低价档 | `deepseek-flash` + 按子任务：清点类 `thinking=disabled`；分析类 `effort=low` |
| 窄决策（该不该扇出 / 该合并还是重跑） | **确定性代码**（规则） | 0 token |
| 独立评估（若启用） | 强力档但**独立上下文** | 不看子 Agent 的推理，只看产物 + 执行记录 |

- 供应商：DeepSeek（已实测）+ 可切预设；无私有化约束。
- 已有先例：`src/runtime/router.ts` 就是"规则式分流不花模型钱"的成功案例，继续沿用这个口味。

**依据**：Model Cascade / Confidence-Gated Control Flow 模式；本项目实测过的缓存命中率与表价可直接进预算表。

## Q7. 效率与体感

**问题**：① 端到端可接受多久？要不要流式？② 前缀能否字节稳定？③ 哪些步骤可不依赖并行？④ 要不要取消、取消后副作用怎么办？

**参考答案（默认假设，可推翻）**：

1. **端到端**：并行段墙钟 ≈ `max(子任务) + 汇总`；3 个子任务目标 < 30s。
2. **流式**：**必须**——已建好的 SSE + 「实时」视图要能同时看到多个子 Agent 的思考与工具卡片（这是本项目的差异化优势）。
3. **前缀稳定**：子 Agent 系统提示固定、工具表**固定序**披露（现有 `toDefinitionsFor` 已是稳定顺序）、时间戳/随机 id 一律不进前缀。目标：子 Agent 之间可共享同一段稳定前缀 → 提高缓存命中（实测同一任务 4 次调用已有 71% 输入命中缓存）。
4. **并行度上限**：`MAX_SUBAGENT_CONCURRENCY=4`（与现有 `MAX_TOOL_CONCURRENCY` 同风格）。
5. **取消**：父任务取消要**级联**到所有子 run（`AbortController` 传播）；本项目工具全只读，取消**无补偿问题**（这是只读边界带来的免费好处，值得写进设计里）。

**依据**：生产级清单的墙钟预算/并行度封顶/可中断点三问；缓存维度要看"命中 token 占比"而不只是"花了多少"。
