# 产品化路线：从 Runtime MVP 到本地可用的代码 Agent

> **定位**：不是一个公开 SaaS 平台，而是**本地单用户、可控写代码的 Agent 工作台**。
> **To C 够用**的定义不是“功能多”，而是：用户第一次打开知道怎么用；任务失败能看懂为什么；每次改文件都能看到 diff、审批、验证和回滚证据；取消后系统真的停下来。
> **简历有分量**的定义不是“用了什么框架”，而是：有一条真实主路径 + 可复现评测 + 可量化指标 + 明确的边界与取舍。

---

## 1. 用户主路径（只优化这一条）

1. 打开本地工作台，选择仓库。
2. 选择“分析”或“修改”，修改时显式打开「允许修改文件」。
3. 输入目标，实时看到思考、工具调用、进度与预算。
4. 模型提出改动 → 看 diff → `allow_file` / `allow_once` / `deny`。
5. 落盘后自动跑宿主复验；失败自动回滚并保留证据。
6. 需要时手动发起「深度验证（L2）」，看到通过/失败/取消。
7. 在 run 报告里复看：改了什么、验了几次、花了多少 token、卡在哪一阶段。

任何不服务这条主路径的功能，都先不做。

---

## 2. To C 验收阈值（建议写进每轮验收）

| 维度 | 目标 | 当前状态 |
|---|---|---|
| 无静默失败 | 所有失败都有状态码、错误事件、可读原因；写操作必须有审批/验证/回滚证据 | ✅ 主链路已具备 |
| 取消 | 用户点取消后 2s 内进入终态；不阻塞事件循环 | ✅ 异步链路已具备 |
| 编辑可靠性 | 20~30 条真实修改任务，成功率 ≥80%，L2 通过率 ≥90% | 🟡 管线评测已建（7/7，真 Docker/审批/回滚/TOCTOU）；真实模型 20~30 条任务待建 |
| 回滚 | hostVerify 失败必须恢复文件，并发出 `change_rolled_back` | ✅ 已有回归 |
| 成本 | 单条小修改平均 <$0.02；能单上下文完成时不得默认走编排 | 🟡 编排成本仍偏高 |
| 首次上手 | 新机器 10 分钟内跑通：安装 → Docker → 打开 UI → 完成一次只读分析 | 🟡 `npm run doctor`、README §1.1~1.3（预期输出/最小验证/常见失败）、`docs/DEMO.md`（10 分钟闭环）已就绪；**fresh-clone 真机冒烟未做** |
| 可观测 | 回答变慢时能定位到模型 / 工具 / 审批 / 验证 / 排队中的哪一段 | ✅ diagnosis + 单 run 报告 |

## 3. 四道门（按顺序，不跳级）

### G1 — 执行不阻塞、可取消（已收口 2026-10-19）

- `spawnAsync` 覆盖 Docker、快照、阶梯、diff、落盘、回滚。
- 超时、输出上限、AbortSignal 全链路。
- 回归：`tests/49`。

### G2 — 验证闭环与证据（已收口 2026-10-19）

- L0 语法 → L1 类型/受影响测试 → L2 全量。
- `strictVerify` 审批前 L2；终态 run 手动 L2（可取消）。
- `verification_*` / `change_applied` / `change_rolled_back` 进入 UI 与单 run 报告。
- 回归：`tests/50`、`tests/41h`。

### G3 — 可复现编辑评测（管线已建 2026-10-20；下一步扩真实模型）

**已完成（确定性管线评测）**：`npm run eval:edit`，独立 fixture，真 Docker + 真审批 + 真落盘 + 宿主复验/回滚：

| 场景 | 期望 | 当前 |
|---|---|---|
| E1 单文件正确修复 | 落盘 | ✅ |
| E2 新增模块 + 测试（批量一次审批） | 落盘 | ✅ |
| E3 语法错误 | 沙箱拦截 | ✅ |
| E4 测试失败 | 沙箱拦截 | ✅ |
| E5 用户拒绝 | 不落盘 | ✅ |
| E6 沙箱绿、宿主红 | 自动回滚 | ✅ |
| E7 审批期间外部改动 | TOCTOU 拒写 | ✅ |

结果：**7/7 命中预期**（5 次审批 / 4 文件落盘 / 1 回滚；平均 11.5s、P95 12.6s、tokens=0）。产物 `reports/EDIT_EVAL.md`。

**未完成（不能夸大）**：这 7 条由脚本扮演模型提出改动，衡量的是管线，不是 LLM 编辑智力。下一阶段要用同一 fixture 扩到 20~30 条真实模型任务，统计成功率、L1/L2 通过率、审批次数、token/成本、重试轮次；并把管线评测接进 CI（Docker 可用时运行）。

### G4 — 成本与体验收口

- 子任务去重读取：同一 run 内同一文件只读一次，或由主 Agent 预读下发。
- 编排门槛：派发前估算“单上下文能否装下”，装得下就走单 Agent。
- 前端：历史 run 对比、失败重试、错误页到 run 详情的跳转。
- 首次上手：✅ `npm run doctor` 已检查 Node / Docker / 镜像 / 端口 / Key 并给修复命令；还剩 README 的 10 分钟引导与 fresh-clone 冒烟。

### G5 — 分发与安全（只有真要公开部署才做）

- API 鉴权、TLS、限流、多用户隔离。
- 容器化服务端、持久化队列、审计日志。
- 这些不是当前本地单用户产品的阻塞项；不要为了“看起来生产化”提前做。

## 4. 简历叙事（用证据，不堆名词）

- 做了**一套共享 Agent Loop**驱动 codebase / research / misc / orchestrator，统一预算、权限、超时、检查点。
- 做了**受控写代码闭环**：Docker 沙箱 → L0/L1/L2 阶梯 → 人工审批 → 落盘 → 宿主复验 → 失败自动回滚。
- 做了**可观测与可复盘**：SSE 实时视图、慢回答诊断、单 run 六阶段归因、token/成本分层。
- 做了**RAG + 混合检索 + rerank**：chunk/embedding 参数可解释，RRF 与 rerank 有实测指标。
- 做了**MCP / function calling / 人机协同**：外部工具桥接、`tool_choice`、`ask_user` / `awaiting_user`。
- 做了**不可信内容边界与红队评测**：工具输出注入扫描、run 污点、删除/宿主命令禁用粘性复用，并在当前批次要求勾选二次确认（Runtime + HTTP 双层 fail-closed）；42 条固定样本有可复跑的检出/误报数字和已知缺口。

面试时优先讲：**为什么这样取舍、哪次实测推翻了我的假设、失败如何回滚、指标怎么复现**。

---

## 5. 现在不该做的事

- 为了“架构先进”重写成 LangGraph / 多进程分布式调度。
- 在 RAG 还没跑真实 embedding 的情况下先上 LoRA。
- 在本地单用户产品里先做多租户和复杂 RBAC。
- 追求 exactly-once；当前明确是 at-least-once + 审批/幂等边界。
- 为了功能数量开放任意 Shell；写路径继续走白名单 + 沙箱 + 审批。
