# 长流式输出的浏览器主线程开销（2026-10-23）

> **回答的问题**：P0-3「画面突然卡死、恢复后一次性补出大量内容」修完之后，浏览器里到底还卡不卡？
> **结论一句话**：事件量小时新旧版无差别；**5 万条增量一次性到达**时，新版主线程阻塞从 **731ms 降到 217ms（-70%）**，
> DOM 节点增长从 **26 万降到 300 个**；仍有 10 次 longtask（最长 123ms），所以这是“显著缓解”，不是“零开销”。

## 1. 方法与边界

- **真实代码路径**：加载真实 `public/index.html`，通过真实 `EventSource` 消费 SSE 帧；不是 DOM 模拟。
- **可控输入**：harness 依次发送 `run_started → model_request → N×llm_delta → model_completed → run_completed`，每条 24 字符。
- **两种模式**：`--gap-ms=0`（一次性写完全部帧 = 切回标签页后的最坏追赶）；`--gap-ms>0`（逐条到达）。
- **指标**：CDP `Performance.getMetrics`（Task / Script / Layout / Style）、`longtask`（>50ms）与 `requestAnimationFrame` 帧间隔。
- **环境**：Windows，Microsoft Edge **155.0.4283.62**，`--headless=new`，1400×900。
- **边界**：headless 与真实桌面浏览器有差异；数字用于**同机前后对照**，不跨设备外推。事件是合成的，峰值比正常模型输出更极端。

复现：

```bash
# 当前版本
npm run perf:stream-ui -- --events=50000

# 修复前对照（cff7786 是 P0-3 修复提交）
git show cff7786^:multi-tool-agent/public/index.html > %TEMP%\mta-old-index.html
npm run perf:stream-ui -- --events=50000 --html=%TEMP%\mta-old-index.html --label=before
```

## 2. 结果

### 2.1 50,000 条增量（burst，最坏追赶）

| 指标 | 修复前 `411a72b` | 修复后 `604668c`+ | 变化 |
|---|---:|---:|---|
| 点击 → 渲染完成 | 1548ms | **994ms** | -36% |
| 主线程 Task 总时长 | 1288ms | **762ms** | -41% |
| 其中 JS | 904ms | **479ms** | -47% |
| 其中 Layout | 150ms | **103ms** | -31% |
| longtask 次数 | 10 | 10 | 持平 |
| 主线程阻塞（TBT，>50ms 部分求和） | 731ms | **217ms** | **-70%** |
| 最长单次 longtask | 167ms | **123ms** | -26% |
| 最大帧间隔 | 167ms | **100ms** | -40% |
| P95 帧间隔 | 150ms | **100ms** | -33% |
| DOM 节点增长 | **261,245** | **300** | **约 -99.9%** |
| 堆增长 | +6.7MB | +9.1MB | 见下方说明 |

**怎么读**：修复前每条 `llm_delta` 都会在「事件流」里建一条永久 DOM 节点（26 万），这是卡死的结构性原因；
修复后事件节点上限 500、文本按增量 append，节点数基本恒定。长任务仍存在（一次性处理 5 万帧本身要花时间），
但单次最长从 167ms 降到 123ms，阻塞总量降 70%。

**堆为什么反而高**：新版保留 500 条事件详情与增量渲染缓存，短时峰值更高；但不再随事件数线性增长，长跑不会持续膨胀。

### 2.2 6,000 条增量（接近一次普通长回答）

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 点击 → 完成 | 282ms | 299ms |
| 阻塞（TBT） | 127ms | 159ms |
| 最大帧间隔 | 83ms | 100ms |
| DOM 节点增长 | 36,280 | 281 |

**怎么读**：这个量级下两者都能在 300ms 内完成，差异在噪声范围内；**不能**用这组数字宣称“新版更快”。
真正拉开差距的是事件数继续增长时的节点线性膨胀。

## 3. 复现口径与遗留

- `npm run perf:stream-ui` 需要本机 Edge/Chrome；可用 `EDGE_PATH` 指定路径。
- 可选门禁：`--max-blocking-ms=2000`（超过则退出码 3）。默认只报告，避免不同机器误红。
- 未覆盖：真实桌面浏览器 + 真实模型长输出（需 Key）、移动端、低端机；这些仍应在上线前补测。
